## Lab Activity Instance
 
# Lab Activity 1: 
setState is used for simple, temporary changes within a single screen, such as updating a counter. Provider is used to manage and share data across multiple screens, such as switching the app between light and dark mode.

# Lab Activity 2:
The model stores and organizes the API data, while the service handles API requests and converts the response into model objects. 
The screen receives the data from the service and displays it through the UI, while also handling user interactions such as searching and opening details. 
This activity follows a separation-of-responsibilities design pattern, making the code more organized, reusable, and easier to maintain.

# Lab Activity 3:
The Cart model stores cart and product data, while the CartService handles DummyJSON API requests for retrieving and adding cart items. 
The CartScreen uses FutureBuilder to display the cart’s loading, error, empty, and successful states. Overall, the model, service, and screen have separate responsibilities, making the code organized and easier to maintain.
